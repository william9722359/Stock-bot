## 已知限制（v3.1.2b 追加，2026-10-23；只追加）

- 臨時休市列算不算「已核證」由程式決定：只採計外部核證檔裡對得上（日期＋列 sha256）的列；核證檔的 sha256 只從寫帳程式以外的一個核可檔讀取，缺檔、sha 不符或列 sha 不符一律算待核，不從分母扣掉。
- 寫帳程式、核證檔和核可檔目前在同一台機器、同一個使用者帳號底下，**沒有作業系統層級的權限隔離**。寫帳方在技術上仍可能改動核證檔或核可檔；目前只靠規則禁止和事後比對 sha256 發現，不是系統擋住。

## 已知限制（v3.1.2b-r1 追加，2026-10-23；只追加）
- 錨點核帳方的檢查是黑名單（排除寫帳方名稱），不是核可名單。
- 上櫃 ETF 不在本次下載的 ETF 代號表（只有上市），只靠代號格式規則擋。
- 沒有作業系統層級的隔離（同一台機器、同一個使用者）。
- 缺 2026-07-09 的夜盤快照，2026-07-13 的前一日核對做不了；沒有補造。
- 2026-07-10 臨時休市仍待核（不影響其他計算）。

## 已知限制（v3.1.2b-r2 追加，2026-10-23；只追加）
- 信任根弱點：寫帳程式與核證清單在同一個使用者底下。同一個使用者可以解開唯讀、在別處偽造一份核證檔，再同時改掉核證清單裡記的 sha；這樣本機的 sha 比對全部通過，偽造的列都會被收。本機的 sha 檔只能抓到「只改一邊」的改動。
- 推上 GitHub 之後，公開 commit（伺服器端時間與 commit sha）可以當外部參考點：本機檔被改就和公開 commit 對不上。在推上去之前，這個外部參考點不存在。
- 本機手做的錨點快照只要填了核帳方名稱就會被收（與上面黑名單是同一個問題），目前靠「錨點方案尚未採用」擋住不生效；採用前會先改成核可名單。
